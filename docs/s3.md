# Prompt for Building Detailed AWS S3 Management Tools

## Tool: S3 Management Tool (`aws-s3-manager`)

### Description

The `aws-s3-manager` tool is designed to provide comprehensive management capabilities for AWS Simple Storage Service (S3) buckets and objects. It allows users to perform a wide range of actions, from listing buckets and objects to creating, uploading, downloading, deleting, and managing bucket configurations like versioning and access control. This tool aims to simplify the interaction with S3, making it easier to manage your cloud storage resources.

### Subcommands and Parameters

1.  **`list-buckets`**: Retrieves and displays a detailed list of S3 buckets.

    * **Description**: This subcommand fetches all S3 buckets associated with your AWS account and presents their names and creation dates.
    * **Parameters**:
        * `--output-format` (optional): Specifies the desired output format. Supported values could include `text` (default, human-readable text output), `json` (JSON formatted output), or `table` (formatted table output).

2.  **`create-bucket`**: Creates a new S3 bucket.

    * **Description**: This subcommand allows users to create a new S3 bucket with specified configurations.
    * **Parameters**:
        * `--bucket-name` (required): The name of the new S3 bucket (e.g., `my-unique-bucket-name`). Bucket names must be globally unique across all of AWS. The tool should perform basic validation on the bucket name format.
        * `--region` (optional, default: AWS CLI default region): Specifies the AWS region in which to create the bucket (e.g., `us-east-1`, `ap-southeast-2`). If not specified, the tool should use the configured AWS CLI default region.
        * `--acl` (optional): Specifies the canned access control list (ACL) to apply to the bucket. Allowed values: `private`, `public-read`, `public-read-write`, `authenticated-read`, `aws-exec-read`, `bucket-owner-read`, `bucket-owner-full-control`. Default is `private`.
        * `--grant-read` (optional): Gives read permissions to the specified AWS accounts or groups (e.g., `id=123456789012`, `uri=http://acs.amazonaws.com/groups/global/AllUsers`). Can be specified multiple times.
        * `--grant-write` (optional): Gives write permissions to the specified AWS accounts or groups. Can be specified multiple times.
        * `--grant-read-acp` (optional): Gives read access to the bucket ACL to the specified AWS accounts or groups. Can be specified multiple times.
        * `--grant-write-acp` (optional): Gives write access to the bucket ACL to the specified AWS accounts or groups. Can be specified multiple times.
        * `--object-lock-enabled-for-bucket` (optional): Specifies whether to enable object lock for the bucket. Allowed values: `true`, `false`. Once enabled, it cannot be disabled.
        * `--tags` (optional): A list of key-value pairs to assign as tags to the new bucket (e.g., `--tags "Environment=Production" "Purpose=Backup"`).

3.  **`delete-bucket`**: Deletes a specified S3 bucket.

    * **Description**: This subcommand permanently removes an S3 bucket. **Note:** The bucket must be empty before it can be deleted.
    * **Parameters**:
        * `--bucket-name` (required): The name of the S3 bucket to delete (e.g., `my-empty-bucket`).
        * `--region` (optional, default: AWS CLI default region): Specifies the AWS region where the bucket resides.

4.  **`list-objects`**: Lists objects in a specified S3 bucket.

    * **Description**: This subcommand retrieves and displays a list of objects within a given S3 bucket.
    * **Parameters**:
        * `--bucket-name` (required): The name of the S3 bucket to list objects from (e.g., `my-data-bucket`).
        * `--prefix` (optional): Limits the results to objects with keys that begin with the specified prefix (e.g., `images/`).
        * `--delimiter` (optional): A character used to group keys (e.g., `/`). Common prefixes are returned in the `CommonPrefixes` list.
        * `--max-items` (optional): The maximum number of keys to return in the response.
        * `--starting-token` (optional): A token to specify where to continue paginated results.
        * `--output-format` (optional): Specifies the output format (`text`, `json`, `table`).

5.  **`upload-file`**: Uploads a local file to a specified S3 bucket.

    * **Description**: This subcommand uploads a file from your local file system to a specified S3 bucket and key.
    * **Parameters**:
        * `--local-file` (required): The path to the local file to upload (e.g., `/path/to/my/document.pdf`).
        * `--bucket-name` (required): The name of the S3 bucket to upload to (e.g., `my-upload-bucket`).
        * `--key` (required): The key under which the file will be stored in the S3 bucket (e.g., `documents/report.pdf`).
        * `--acl` (optional): Specifies the canned ACL to apply to the uploaded object.
        * `--grant-read` (optional): Gives read permissions to the specified AWS accounts or groups for the object. Can be specified multiple times.
        * `--grant-full-control` (optional): Gives full control permissions to the specified AWS accounts or groups for the object. Can be specified multiple times.
        * `--content-type` (optional): The MIME type of the content being uploaded (e.g., `application/pdf`).
        * `--metadata` (optional): Custom metadata to be stored with the object as key-value pairs (e.g., `--metadata "Author=John Doe" "Version=1.0"`).
        * `--tags` (optional): A list of key-value pairs to assign as tags to the uploaded object.

6.  **`download-file`**: Downloads an object from a specified S3 bucket to a local file.

    * **Description**: This subcommand downloads an object from a specified S3 bucket and key to your local file system.
    * **Parameters**:
        * `--bucket-name` (required): The name of the S3 bucket to download from (e.g., `my-download-bucket`).
        * `--key` (required): The key of the object to download (e.g., `images/logo.png`).
        * `--local-file` (required): The path to the local file where the object will be saved (e.g., `/path/to/my/downloaded_logo.png`).

7.  **`delete-object`**: Deletes a specified object from an S3 bucket.

    * **Description**: This subcommand permanently removes an object from a specified S3 bucket and key.
    * **Parameters**:
        * `--bucket-name` (required): The name of the S3 bucket containing the object (e.g., `my-archive-bucket`).
        * `--key` (required): The key of the object to delete (e.g., `old-data/file.txt`).
        * `--version-id` (optional): If the bucket has versioning enabled, specifies the version of the object to delete. If not specified, the latest version is deleted (a delete marker is added).

8.  **`delete-objects`**: Deletes multiple objects from a specified S3 bucket.

    * **Description**: This subcommand allows users to delete multiple objects in a single request.
    * **Parameters**:
        * `--bucket-name` (required): The name of the S3 bucket containing the objects.
        * `--objects` (required): A JSON string or a file path to a JSON file specifying the objects to delete. The format should be: `'[{"Key": "object1.txt"}, {"Key": "path/to/object2.dat"}]'`. If versioning is enabled, you can optionally include the `VersionId`: `'[{"Key": "object1.txt", "VersionId": "version1"}, {"Key": "object1.txt", "VersionId": "version2"}]'`.

9.  **`enable-versioning`**: Enables versioning for a specified S3 bucket.

    * **Description**: This subcommand enables versioning for an S3 bucket, allowing you to keep multiple versions of an object in the same bucket.
    * **Parameters**:
        * `--bucket-name` (required): The name of the S3 bucket to enable versioning for.
        * `--region` (optional, default: AWS CLI default region): Specifies the AWS region where the bucket resides.

10. **`disable-versioning`**: Suspends versioning for a specified S3 bucket.

    * **Description**: This subcommand suspends versioning for an S3 bucket. Existing versions are retained, but new uploads will overwrite the current version.
    * **Parameters**:
        * `--bucket-name` (required): The name of the S3 bucket to suspend versioning for.
        * `--region` (optional, default: AWS CLI default region): Specifies the AWS region where the bucket resides.

11. **`get-bucket-versioning`**: Gets the versioning configuration for a specified S3 bucket.

    * **Description**: This subcommand retrieves and displays the versioning status of an S3 bucket (e.g., `Enabled`, `Suspended`, `Off`).
    * **Parameters**:
        * `--bucket-name` (required): The name of the S3 bucket to get the versioning configuration for.
        * `--region` (optional, default: AWS CLI default region): Specifies the AWS region where the bucket resides.
        * `--output-format` (optional): Specifies the output format (`text`, `json`, `table`).

12. **`get-bucket-acl`**: Gets the access control list (ACL) for a specified S3 bucket.

    * **Description**: This subcommand retrieves and displays the ACL of an S3 bucket, showing the permissions granted to various grantees.
    * **Parameters**:
        * `--bucket-name` (required): The name of the S3 bucket to get the ACL for.
        * `--region` (optional, default: AWS CLI default region): Specifies the AWS region where the bucket resides.
        * `--output-format` (optional): Specifies the output format (`text`, `json`).

13. **`set-bucket-acl`**: Sets the access control list (ACL) for a specified S3 bucket.

    * **Description**: This subcommand allows users to set the ACL of an S3 bucket using either a canned ACL or by specifying individual grants.
    * **Parameters**:
        * `--bucket-name` (required): The name of the S3 bucket to set the ACL for.
        * `--region` (optional, default: AWS CLI default region): Specifies the AWS region where the bucket resides.
        * `--acl` (optional): Specifies a canned ACL to apply.
        * `--grant-read` (optional): Gives read permissions to the specified AWS accounts or groups. Can be specified multiple times.
        * `--grant-write` (optional): Gives write permissions to the specified AWS accounts or groups. Can be specified multiple times.
        * `--grant-read-acp` (optional): Gives read access to the bucket ACL. Can be specified multiple times.
        * `--grant-write-acp` (optional): Gives write access to the bucket ACL. Can be specified multiple times.
        * `--access-control-policy` (optional): Specifies the ACL as an XML file.
